# Leader 低 PWM 接地校正（2026-11-16）

## 原因與測試狀態

前兩趟 Leader 直線在車上距離 1 m／2 m 時，輪速實測 TPS 都遠高於目標。`Arduino-ugv` 的 Leader 韌體 `src/main.cpp`（`leader1-pi-usb` 分支，SHA `ffe46d9e58b35c6e5593fb1f9e169c7e304a7e8f`）使用

```text
PWM = 55 + 0.14 × |target TPS| + 0.10 × (target−measured TPS) + 0.08 × integral
integral 限制於 −220..+220
```

在兩趟 CSV 的穩態區間，按 STATUS 的 target、measured TPS 和 PWM 反推，左右輪的 integral 中位數都約 −218 到 −221；若固定 integral = −220 預測 PWM，1 m 區間左右各 170／170 筆與回報 PWM 差不超過 1，2 m 區間左右各 312／312 筆也相同。因此**降速積分已到負限幅**，控制器當時無法再將 PWM 降低。STATUS 與 PWM 有取樣／四捨五入誤差，但大量樣本吻合。

操作者確認 Leader 接地、靜止、馬達電源可立即切斷，周圍有淨空；每趟先做 IMU 校正與接地 PWM 80／800 ms 預檢，通過後送 STOP。操作者將 MPU 放回 0 cm 並再次確認後才開始正式掃描。兩次測試都只動 Leader，F1/F2 未啟動。兩支 Pi 程式均在 `finally` 送 STOP；目前已收到 Nano STOP ACK、控制程序退出，未燒錄或修改韌體。

## 已起轉後逐級降低 PWM

Pi 執行 `leader_pwm_running_sweep.py`，部署 SHA-256 `586fe7ed31df90f1133368208deec4450104bf23071e57e6de41a9ea76fa864a`。先以 PWM 80 起轉，再不停止地改為 60、55、50、45、40；每一段 Nano 命令最多 1200 ms 到期，Pi 約 0.55／0.75 s 切到下一段。[CSV](running.csv) 數值原樣保存，Git 版本只將 CRLF 換成 LF，SHA-256 `9eb7579bfa6a005282c111b2846021e4a7839d704ea8402fc97e220b5174ace6`（Pi 原檔 SHA-256 `bbc3e0b8c8581d9c26444689481ca2a7bc28640b437425af01260c9ed7bd7302`）。

## 對控制器的意義

單純加大負積分限幅雖能降低穩態 PWM，可能讓車輪落回起轉死區、產生停走振盪。比較合理的候選是分開**短暫起轉輸出**與**已轉動時的低速前饋／PI**，並加入適當的積分抗飽和；需先在安全短路線驗證低速是否可連續控制。這兩趟掃描尚無充分資料指定新 PWM 或 PID 數字，也未校正直線的 `ticks/mm`。Leader 輪徑在韌體仍設暫定 65 mm；兩趟地面／里程約 1.147 的比例若全由輪徑造成，候選接地有效直徑約 74.6 mm，但必須先實量輪胎外徑、刻度距離並核對既有每圈 encoder count，不能直接寫入韌體。

## 操作者補充的橫向幾何量測

2026-11-16 操作者量得 Leader 左輪外緣到右輪外緣 **160 mm**、兩輪內緣間 **115 mm**。在左右輪同寬、輪面平行且尺量點對稱的假設下，每輪名義寬度 `(160−115)/2 = 22.5 mm`，左右輪幾何中心距 `(160+115)/2 = 137.5 mm`。韌體目前 `WHEEL_TRACK_MM=130 mm` 是先前暫定值；幾何中心距比它大 7.5 mm（約 5.8%）。差速車轉向的**有效輪距**還會受輪胎接地、滑移與轉向方式影響，不能只憑尺量直接把 130 改為 137.5。此橫向量測也**不是單顆輪胎直徑**，因此尚未解決上述直線里程尺度；單顆左右輪外徑另待量測。
