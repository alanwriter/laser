## 影片與地面距離初步核對

操作者提供 `20261116_ALAN0526.MP4`（A7C II，H.264 MP4、直式 2160 × 3840、29.97 fps、52.05 s），[影片抽幀](video_contact_sheet.jpg)可見 Leader 沿膠帶中心線朝相機行走，末段超過預定距離。原影片的附檔路徑在抽幀後已無法再次讀取；本資料夾保留抽幀及原始 CSV。影片最後車體部分超出畫面，且 MPU 在車體上方，單靠斜視畫面無法得到精確的終點毫米座標。

操作者現場以**同一 MPU6050 垂直投影**作起終點，回報實際約比 2 m 多走 300 mm，即約 2300 mm。此數字是現場估值，尚無精確終點尺讀或完整地面透視標定；下表按 2300 mm 示範估算，不能當作已確定到毫米的真值。

| 指標 | 以約 2300 mm 地面距離估算 |
|---|---:|
| 車上終點里程 / 地面位移 | 2002.7 / 2300 ≈ 0.871 |
| 車上少記的距離 | 約 297 mm，約為地面位移的 12.9% |
| 地面距離 / 車上里程校正因子 | 約 1.148 |
| 實際平均地面速度 | 約 2300 / 47.41 ≈ 48.5 mm/s |
| 實際平均速度 / 25 mm/s 巡航設定 | 約 1.94 |

這趟至少提示兩種不同問題：閉環輪速實測 TPS 高於目標，解釋為何約 47 s 就結束原本按 25 mm/s 需約 80 s 的路程；而**多走約 300 mm 才達車上 2000 mm**，表示里程估計相對地面偏小，不能單靠降低巡航命令來修正停車距離。可能來源包括每輪 count→mm 換算、輪胎接地有效周長、起終點對應或現場量測誤差；本趟不足以單獨判定哪一項，也不應直接改 Nano `CONFIG`。下一步需同一 MPU 投影基準重複一趟短直線，記錄實際每個 200 mm 刻度的通過時間／對應 CSV，再分開估速度迴路與里程比例。

## 韌體修正順序（依此趟 CSV）

Leader 原始碼的 `LEFT/RIGHT_TICKS_PER_MM = ticks_per_rev / (π×wheel_diameter)` 同時用於 `count→mm` 里程和 `mm/s→target TPS`。本趟兩輪最後 count 11936／11986，累積距離約 2003 mm；若實際為約 2300 mm，每輪有效 ticks/mm 約 5.19／5.21，現設定約 5.96／5.99。這只給出候選比例，不能由單趟約略終點決定究竟應修正輪徑、ticks/圈或硬體漏計。

將每筆目標 TPS 依現有 ticks/mm 積分，這趟 47.4 s 的**目標輪距離約 1147 mm**，但累積 encoder 距離約 2003 mm。5–40 s 穩態期間，左／右實測 TPS 中位數均約 300，目標中位數約 131／162，PWM 中位數約 43／48；左輪 312/312 筆、右輪約 311/312 筆實測 TPS 高於目標。10 ms TPS 有量化，但累積 count 也確認超速不是單筆量化假象。

因此優先檢查兩個獨立層次：

1. **距離比例**：同一 MPU 地面投影基準重複短直線，精讀終點；核對實際輪徑與 10 圈編碼器 count、A/B invalid transitions，再估每輪有效 ticks/mm。直線下左右 count 與航向相近，先查共同尺度，不先改四相解碼器或左右輪差異。
2. **輪速閉環**：用每輪 target／measured TPS、PWM、count 的穩態時窗量測低速可控範圍；現有固定起步 PWM 55、速度前饋 0.14 PWM/TPS、`Kp=0.10`、`Ki=0.08` 可能讓低速輸出偏大。先依實測建立左右各自的 PWM–速度關係，再調前饋與 PID，並驗證命令 25 mm/s 是否能持續達成。

幾何常數同時影響輪速目標與里程；只把 25 mm/s 的 Pi 命令調低，不能修正 `count→mm` 的距離偏差。兩層都須分開驗證後，再進行三車編隊。
