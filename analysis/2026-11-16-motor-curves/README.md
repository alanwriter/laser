## 接下來的逐車實驗

三車依序、每次只動一台。每車以正常電池、正常載重、車輪接地和同一地面測試，
記錄車名、韌體版本、電池電壓、左右 PWM、兩輪 TPS/count、命令時間、起終點
MPU 地面位置、航向與影片。每個 PWM 配對從同一起點重新擺位；先量從靜止
起轉，再量已起轉後維持約 1–2 s 的輪速。各點至少重複三次，排除加速前段，
由後段求中位 TPS 與變動幅度。量測時設航向、路程、時間及通訊失效停止護欄；
舊 Leader PWM 40 護欄事件不會被當成有效穩態點。執行前仍需確認當下淨空、
斷電方式、車輪接地及相機，預檢後放回起點再出發。
單點量測程式為 `pi_rover/motor_curve_point.py`：一次只量一車、一組左右 PWM，
預檢後要求再次確認擺位；每個 MOTOR 命令 900 ms 到期，期間持續檢查 Nano
故障、IMU、車上路程與 ±20° 航向護欄，離開時送 STOP。此程式已做本機離線
護欄／錯誤停止測試，並部署到 Leader。一次 PWM 80／800 ms 預檢後，
原定 PWM 60／55 配對因左右 count 879／679、航向 −16.2° 而取消；
**尚未執行正式單點曲線量測**。

操作者若觀察到輪胎空轉或車體滑移，該試次標為無效並重做，原始紀錄及原因
仍保留；有效試次不以打滑解釋輪速或里程誤差。左右同 PWM 不等速先作為每輪
特性量測，不由此推論卡滯。若航向護欄使配對無法維持到穩態，該點也不納入
穩態曲線，改用較接近直行的左右 PWM 配對另測。

先畫每車左右輪的「輸入 PWM → encoder TPS」，並分別標示起轉成功率與已起轉
穩態區間。只有當兩輪在同一 TPS 區域都能連續、可重複地控制，才標出該車
共同可控的 TPS 交集。TPS 換成真實地面 mm/s 需再用同一趟地面尺與輪側轉數
核對；Leader 1 m 命令停在地面 116 cm，不能直接套韌體現有 ticks/mm 當地面真值。

差速設計之後使用各輪各自的反函數選 PWM。若地面輪速為 `vL`、`vR`、有效
輪距為 `b_eff`，車體速度與角速度為 `v=(vL+vR)/2`、`ω=(vR−vL)/b_eff`。
幾何輪中心距約 137.5 mm 是起始量測值，`b_eff` 須用有效試次的左右轉彎角度
再估計；尚不能拿現有短掃描指定可靠轉彎半徑。

## 同速直線如何驗證

先用每輪閉環命令給相同的目標 TPS，記錄同時的左右實測 TPS、count、PWM、
IMU 航向，再用固定相機看 MPU 是否沿地面中心線行走。2026-11-16 尺讀 1 m
複測的終點 count 左／右 5992／5988，相差約 0.067%，車上航向 −0.1°、
`y=+0.9 mm`；這已支持「兩輪 encoder 進度近乎一致、車上估計直行」，
但本趟尚無獨立精讀地面橫向偏差的影片。當時地面 MPU 走 116 cm，車上
只記 100.3 cm；所以同速直線能驗證左右對稱與航向，**不能單獨驗證地面
距離比例或 PWM 曲線**。新一趟應把地面直線偏差、車輪實際轉數與 Nano
count 同時記下，且若觀察到打滑就排除重做。

### 40 cm 固定同輪速驗證：航向護欄停止

操作者確認車輪接地、起點與淨空、固定相機錄影，並在接地預檢後把 MPU 放回
0 cm。Leader Pi 使用 `leader_straight_calibration.py --fixed-equal-wheels`，
固定送左右 `VELOCITY 18,18`，每個命令 180 ms 到期；不由 Pi 加航向修正。
預檢 PWM 80／800 ms 左／右 count 739／785（隨後 STATUS 741／787）、
車上航向 +2.3°，旗標通過並 STOP。正式跑在 6.885 s 因車上航向達
**−20.3°** 超過 ±20° 護欄而自動 STOP，未達預定 400 mm。
Nano STOP ACK、程序退出，`fault_code=0`；F1/F2 未行走。

| 終點車上量 | 左輪 | 右輪 |
|---|---:|---:|
| encoder count | 1483 | 1237 |
| count／時間平均 | 215.4 TPS | 179.7 TPS |
| 按當前 profile 的輪距離 | 249.0 mm | 206.6 mm |

終點車上 `(x,y)=(223.3,−36.1) mm`。左右 count 相差 246，約為兩輪平均的
18.1%；按目前 profile 輪距 130 mm，輪差預測轉角約 −18.7°，與 MPU
−20.3° 同方向且接近。3–6 s 的 STATUS 單點 TPS 中位數兩輪都約 200，
但瞬時 TPS 以約 100 TPS 階梯跳動，**會掩蓋累計 count 的速度差**；判斷
等速應優先比較同時間窗的 count 斜率。該段反推的兩輪速度積分也接近負限幅
−220；控制器雖對兩輪同下 18 mm/s，仍無法讓實際 encoder 輪速一致。
這趟操作者回報沒有看見打滑，左輪停在膠帶中心線上，車軸約偏 4 cm、
車頭偏得更多，支持明顯向右偏航。車軸估讀不是 MPU 地面投影的精確橫向距離，
後者仍待停車照片或影片核對。車上里程位置不能直接
當作地面真值。[原始 CSV](leader_equal_400mm_aborted.csv)、
[encoder A/B 回報](leader_equal_400mm_aborted.encoder.txt)、
[對時圖](leader_equal_400mm_aborted.png) 保留此中止試次供診斷，不算作
「同輪速已達成」的曲線驗證。

此結果與同日 1 m 直線的左右 count 幾乎相等並不矛盾：前者固定兩輪命令，
不做上位航向修正；後者的 Pi 直線控制器會依橫向與航向誤差調整左右目標，
可把車拉回中心。下一步應量出每輪在已起轉狀態的可重複 PWM→count 斜率，
並修正每輪低速前饋／積分限幅，再以同一固定命令短直線複驗。
